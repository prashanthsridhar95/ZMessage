# Privacy: data inventory and threat model

*Last updated 9 November 2026 (text version 1). This is a technical description written by the developers, not legal advice and not reviewed by a lawyer. The plain-language version people read is in the app, Settings, Privacy and terms (`LegalText` in `:domain`); a test keeps its hosts and permissions the same as the ones below. See [LEGAL_NOTES.md](LEGAL_NOTES.md).*

## Where the app talks to the internet

Only these hosts, and only for the feature named. A unit test (`LegalPolicyTest`, with `ManifestPolicyTest`) compares this list with the hosts written in the code and with the page in the app.

| Host | Feature | Sent |
|---|---|---|
| `www.google.com` | Brand logos (favicon service); the in-app Google Images page when you tap "From the web" | A well-known website name; the sender's name as the search text. Google's page may use its own cookies |
| `icons.duckduckgo.com` | Brand logos (second source) | A well-known website name |
| `query1.finance.yahoo.com` | Market prices (opt-in) | The tickers in your watch list |
| `query2.finance.yahoo.com` | Stock-name suggestions (opt-in) | The letters you type in the add-stock box |
| `api.flightradar24.com` | Live flight status (opt-in) | An airline code and flight number |
| `indianrailapi.com` | Live train status (opt-in; needs your own key from that service; HTTPS only) | The train number, the journey date (the day the run started, yyyymmdd) and your own key |
| `www.googleapis.com` | Backup to your own Google Drive (opt-in, scope `drive.appdata`) | One encrypted file |

A brand's own website is also asked for its icon (`https://<brand>/apple-touch-icon.png`), from a fixed list of well-known brands in the app. Texts the app sends (code sharing, balance check) are SMS from the SIM, not internet requests. The app sets no cookies of its own, so it shows no cookie banner (see LEGAL_NOTES.md).

## Permissions

| Permission | Why |
|---|---|
| `READ_SMS` | Read the inbox, and the text and pictures of picture messages (MMS) in the phone's MMS store, to organise payments, bills and codes; never writes or deletes. No other permission is needed for MMS |
| `RECEIVE_SMS` | Live alerts and code sharing; the text is read in memory and dropped |
| `SEND_SMS` | Only "Share codes with trusted people" and "Check balance by SMS"; Google Play restricts it, so the app is for direct installs |
| `INTERNET` | Only the hosts above |
| `POST_NOTIFICATIONS` | Reminders, digest, code buttons, flight notification |
| `RECEIVE_BOOT_COMPLETED` | Put alarms back after a restart |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC` | Reading a very large inbox; following a train under way or a flight in the air (opt-in) |
| `POST_PROMOTED_NOTIFICATIONS` | Android 16 Live Update for the flight notification; gives no access to anything |

Notification access (RCS chat messages) is a system setting, not a manifest permission, and is off until the person allows it. Chat (RCS) conversations in Google Messages are not in the phone's SMS or MMS store; the app sees only the sender and the text a notification shows (its expanded text and messaging-style entries when present), never a rich message's banner image or buttons.

Suggestions, spam scoring, search phrases, alerts and summaries are computed on the phone from messages already in memory; nothing is downloaded or sent. An on-device language model (Gemini Nano) is supported through a small interface but is only used when the phone provides one, and every answer it gives is checked against the message text.

There is no account, no analytics and no crash reporter (the on-phone black box above is only ever shared by you). The only network use is the logo setting (on by default, can be turned off), the market strip and its stock-name suggestions (off until you turn it on; what you type in the add-stock box is sent to Yahoo Finance while you type, and is not stored), live flight status (off until you turn it on; the airline code and flight number are sent to Flightradar24, nothing else, when Home comes to the front, every 30 seconds while a flight sheet is open, and every 30 seconds while the ongoing "flight in progress" notification is up) and the optional backup to your own Google Drive (off until you turn it on and sign in).

## Threats considered

| Threat | Mitigation |
|---|---|
| App exfiltrates messages | `INTERNET` is used by five files: `LogoFetcher` (a brand's website name), `QuoteFetcher` (tickers from your watch list, and what you type in the add-stock box to suggest names), `FlightFetcher` (opt-in: an airline code and flight number, to one host, with no redirects), `TrainFetcher` (opt-in, needs your own key: a train number, the run's start day and the key, to one host over HTTPS, with no redirects) and `DriveBackupClient` (opt-in: one PIN-encrypted backup file to your own Drive's private app folder); a unit test enforces that no other file touches the network and which hosts they may call |
| The cache database is copied off the phone and read | Each entry is AES-256-GCM encrypted with a Keystore key that cannot be exported, so the file alone is unreadable; backups and device transfer exclude databases; a damaged or old entry is dropped, never trusted |
| Messages end up in a cloud backup | Android Auto Backup is on only to carry one file, `auto_backup/zyke-backup.bin`, which holds the encrypted setup and never messages; the backup and transfer rules include only that file and exclude preferences, databases, every other file, external storage and the app root, and a unit test pins this. Cloud backup is skipped on a phone that cannot encrypt it |
| A backup file is stolen and guessed at | The file is AES-256-GCM encrypted with a PBKDF2 (600,000 rounds) key from your PIN. A 6-digit PIN has only 1,000,000 possibilities: this keeps casual finders out, but someone holding the file could try them all offline. The app says so and offers a long passphrase instead; a wrong PIN on the restore screen waits a second per try |
| Someone looks over the shoulder / screen capture / recent-apps preview | Optional `FLAG_SECURE` ("Block screenshots") |
| Malicious or malformed SMS crashes or stalls the app | Classifier never throws, parses at most 4096 characters, fuzz and hostile-input tests |
| Another app drives ours | Only the launcher activity is exported; the notification listener service and the three receivers (widget, morning alarm, restart) are not exported, and a unit test pins the list |
| A rogue app fakes an incoming text to the live-alerts receiver | It is the only exported receiver, guarded by the system-only `BROADCAST_SMS` permission, disabled until the person opts in, and it only ever shows a notification |
| A code is passed on that should not be, or twice, or in a flood, or from an old message | Hard blocks in `CodeSharing.decide` that no setting overrides (financial, account-security, senders that are not the allowed services' own), a service match plus an OTP classification, 5 an hour per person, no repeat of the same code, nothing older than 5 minutes, only the live receiver path (pinned by `CodeSharingPolicyTest`), off by default, a quick pause and a window |
| A code shows on the lock screen or in the clipboard preview | The notification is private (the lock screen says "A new one-time code"), and the copied code is marked sensitive |
| Someone sees your money figures over your shoulder | Optional "Hide amounts": every amount in the app (screens, message text, snackbars, spoken descriptions) shows as dots, and so do notifications and the widget. Showing them asks for the phone's own screen lock (fingerprint, face, PIN, pattern or password) through the system's confirm-credential screen, then reveals for 60 seconds, or until you leave the app. Nothing about the check is stored; the app never sees a fingerprint, face or PIN. A phone with no screen lock falls back to a tap that shows amounts for 5 seconds |
| Someone else picks up an unlocked phone | Optional app lock: the phone's own fingerprint, face or screen-lock prompt after 30 seconds away |
| A train shows to someone who sees your lock screen | Same switch and same default as for flights: the route, times and status show there until you turn off Settings > Flights and trains > "Show flight and train details on the lock screen" (then only "Train journey in progress") |
| A flight shows to someone who sees your lock screen | By default the flight notification shows the route, times and status there (and on the always-on display, where your phone allows it). Turn off Settings > Live flight status > "Show flight details on the lock screen" and it says only "Flight in progress"; the phone's per-app and global lock-screen notification settings also apply |
| Digest or widget shows private details | The notification is private on the lock screen; the widget is something you add yourself and shows only short lines such as "Insurance expires tomorrow" |
| Reverse engineering | R8 minification and obfuscation in release |
| Sensitive text in logs or bug reports | No logging of message content; the parsing report masks digits, names, links and handles and is shared only by the user, through a private non-exported `FileProvider` limited to one cache folder |

## Known limits

- A 6-digit backup PIN is weak against someone who has the backup file itself (one million guesses, each slowed by 600,000 rounds). Use a long passphrase for real protection. A forgotten PIN or passphrase cannot be recovered by anyone.
- Android decides when its Auto Backup uploads the file; the app only controls how often the local file is refreshed. Turning that option off deletes the local file but cannot delete a copy Android already uploaded.
- Backups already uploaded to your Drive stay there when you switch Drive backup off; remove them in Google Drive settings, Manage apps.
- The app lock uses the phone's screen-lock prompt, so anyone who knows the phone's PIN can open the app. It is off by default.
- "Hide amounts" covers what the app draws and posts. A notification posted while amounts were shown keeps its text, and a year-in-review picture or report you choose to share carries real figures.
- The morning digest alarm is inexact and, after a restart, comes back only because the app registers for the boot broadcast.
- A device with root or a debugger attached can read app memory.
- The masking in the diagnostics report is heuristic; review it before sharing.
