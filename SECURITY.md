# Security and privacy

Zyke Message reads the SMS on the device to organise payments, bills and OTPs. Everything happens on the
phone.

## What the app guarantees

- **Almost no network.** The `INTERNET` permission exists for four settings: "Fetch brand logos" (on by default, can be turned off), the market strip, "Live flight status" and "Live train status" (all three off until you turn them on). Only these files can use it (besides the optional Drive backup). `LogoFetcher.kt` sends a well-known brand's website name to a public icon service; `QuoteFetcher.kt` sends the tickers in your watch list (such as `RELIANCE.NS`) to Yahoo Finance's public price service, and, while you type in the add-stock box (market strip switched on only), the few letters typed so it can suggest names; that text is not stored. `FlightFetcher.kt` (flight status switched on only) sends one airline code and flight number, such as `6E2345`, to Flightradar24's public flight endpoint when Home comes to the front, every 30 seconds while the flight sheet is open and every 30 seconds while the in-flight foreground service (`FlightTrackingService`, type dataSync, not exported, no network code of its own: it asks only through `FlightService` and this one fetcher) watches a flight in the air; it follows no redirects, sends no cookies or identifiers, and never the PNR, the date or any message text. The service runs only with live status on, is not started by the boot broadcast, takes no exact-alarm permission, and writes no flight number, route or status to the log (`FlightTrackingPolicyTest`). The flight notification shows the route and times on the lock screen by default (it is not a money figure); "Show flight details on the lock screen" in Settings > Live flight status turns that off, and the one added permission for it, `POST_PROMOTED_NOTIFICATIONS` (Android 16 Live Updates, a normal permission), gives no access to anything. `TrainFetcher.kt` (train status switched on only, and only once you have saved your own train data key) sends one five-digit train number, such as `12633`, the date that run started and your key to Live Train Status, Indian Rail API (`indianrailapi.com`), over HTTPS only, the same way (no redirects, no cookies or identifiers, never the PNR, the stations or any message text), from Home, the open train sheet and `TrainTrackingService` (a twin of the flight service: dataSync, not exported, no network code of its own, never started by the boot broadcast, at most two trips tracked with flights; `TrainTrackingPolicyTest`). The key is kept like the UAN: in `train_key_device`, excluded from every backup, never logged, never in a notification, and removed from the text the developer tools can share; it is not in the saved instance state of the key field. After three answers in a row that refuse the key or report a limit, a journey is not asked about again until the key is saved again or the next day. The provider's address and reply format are taken from its documentation and are not verified against the live service. None of them ever sends message text, numbers or amounts, and a unit test keeps network code out of every other file and pins each host.
  `ManifestPolicyTest` fails the build if that changes.
- **Least privilege.** `READ_SMS` reads your messages, including the text and pictures of picture messages (MMS); it never writes to or deletes them. Chat (RCS) messages are seen only through the optional notification access, as the text a notification shows. `RECEIVE_SMS` (code alerts) and `SEND_SMS` ("Share codes with trusted people") are asked for only when you switch those features on; sharing sends only a login code and the sender's name, by SMS, to the people you chose, and never a bank, UPI, card, payment, government, insurer or phone-company message. "Recent codes seen" on that page keeps only times, sender headers (a phone-number header masked to two digits), the sender's name and the outcome, never a code, message text or number, and is left out of backups. Any sender can be chosen from the codes you have received (in the last 90 days), but a bank, card, UPI, payment, wallet, broker, exchange, government, insurer or phone-company sender cannot be chosen, a payment-worded text is never forwarded whatever the sender, and choosing a sender for a person is an explicit tap ("Share this sender's codes" asks who gets it); chosen senders are stored as names only and never lift the hard blocks. "Check balance by SMS" also uses `SEND_SMS`, asked for only when you first tap Send: it texts your bank's enquiry number the exact words you confirmed (never a PIN, MPIN or password, which Zyke refuses to store or send), at most once per account every 2 minutes, never on a schedule. Google Play restricts `SEND_SMS`, so those features are for builds installed directly.
- **Nothing leaves unless you send it.** The one exception is the masked parsing report you choose to share.
  It goes through a private, non-exported `FileProvider` limited to one cache folder, with read access granted
  to the app you pick for that one file only.
- **Backups are opt-in and encrypted.** Android Auto Backup is on only to carry one file, `files/auto_backup/zyke-backup.bin` (the setup, encrypted with a key from your PIN); every other file, preference and database is excluded. Backup to your own Google Drive is off until you switch it on. See `docs/PRIVACY.md`.
- **Small footprint of stored data.** The app stores only message *ids* (read / pinned / archived marks),
  dismissed tips, budgets and two settings, in app-private storage. Message text is never persisted.
- **Release hardening.** Release builds are minified and obfuscated with R8.
- **Screenshot protection.** Settings has a switch that blocks screenshots and hides the app in the
  recent-apps view.

See [docs/PRIVACY.md](docs/PRIVACY.md) for the data inventory. The person-facing text is in the app (Settings, Privacy and terms, and Open-source licences); [docs/LEGAL_NOTES.md](docs/LEGAL_NOTES.md) says what is and is not covered, and that a lawyer should review it before any public release. SMS permissions are restricted by Google Play, so this app is for direct installs (sideloading), not the Play Store.

## Reporting a vulnerability

Please do not open a public issue. Email the maintainer (see the repository owner's profile) with the details
and steps to reproduce. You will get an acknowledgement within a few days.

When sharing an SMS that is mis-parsed, use *Settings → Parsing health → Share report*. It writes a text file
with digits, names, links and handles masked and opens the system share sheet, so you choose where it goes.
Check the file before sending it.
